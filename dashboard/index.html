How detection works

Requests become features describing account and source history, endpoint rarity, response patterns and short bursts of activity. Models trained on earlier traffic score unusual combinations.

A high anomaly percentile puts a request near the top of the learned baseline. Ordinary-looking requests can still be important evidence.

Models

The models on this site were trained on the Log & Order challenge dataset, which contains 180,800 access-log requests from August 2025 through March 2026.
They provide a working example of detecting unusual activity in an organization’s traffic.

Training

The deployed Gaussian mixture and deep autoencoder models were fitted on requests recorded from August 2025 through February 2026. Each request is represented by features describing account and source-address history, endpoint rarity, response patterns and recent request bursts. For example, a successful response for a resource that an account was previously denied contributes to its anomaly score.

Benchmarks

The benchmark compares how effectively each method ranks unusual requests in the challenge dataset. Models were fitted on August–January traffic, with settings selected using simulated anomalies in February. March traffic was reserved for evaluation against 22 manually annotated requests, including two contextual records.

The table shows the research comparison used to assess the detection methods. The deployed models were subsequently fitted on the full August–February history. “Contextual” features incorporate earlier account behavior; “Raw fields” use the seven access-log fields directly.
